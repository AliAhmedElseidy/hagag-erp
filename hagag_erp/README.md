# Hagag ERP

تطبيق Frappe مخصص (Custom App) بيضيف براندنج، تكامل واتساب، ومساعد ذكاء اصطناعي فوق نظام ERPNext الأساسي لشركة حجاج.

## الميزات

### 1. البراندنج (Branding)
- إخفاء أي إشارة لكلمة Frappe أو ERPNext من الواجهة
- ألوان مخصصة (اللون الأساسي: #d97706 برتقالي)
- شعار وأيقونات PWA مخصصة
- دعم Dark/Light mode
- ملفات البراندنج: public/css/hagag_desk_v16.css و public/js/hagag_desk_v16.js

### 2. تكامل واتساب
- api/whatsapp.py يتصل بسيرفر واتساب منفصل في ~/wa-bridge

### 3. المساعد الذكي (AI Gateway)
- api/gemini_gateway.py يوصل المستخدم بمساعد ذكي يفهم عربي
- الواجهة: أيقونة شات في ركن الشاشة public/js/hagag_chat.js
- الشخصية: ممنوع يذكر ERPNext أو Frappe أو MCP، بيتكلم باسم نظام حجاج بس

## البنية التقنية للمساعد الذكي

سؤال المستخدم بالعربي يروح لـ hagag_erp.api.gemini_gateway.ask_gemini (Frappe endpoint)
بعدين لـ Gemini API (نموذج gemini-3.1-flash-lite) بيستخدم function calling
بعدين لـ MCP Server (Casys-AI/mcp-erpnext v2.6.0) شغال في Docker على بورت 3012 داخلي بس
بعدين Frappe REST API وبيوصل لبيانات ERPNext الحقيقية

صلاحيات المساعد حاليًا: قراءة فقط (Customer, Sales Invoice) عن طريق مستخدم ai@hagagco.com بصلاحية محدودة. لسه معندوش صلاحية إنشاء أو اعتماد أو حذف مستندات.

## الإعدادات المطلوبة في site_config.json

تتضاف بأمر bench set-config، مش هاردكودد في الكود:
- gemini_api_key: مفتاح Gemini API
- mcp_token: توكن مصادقة MCP server
- mcp_url: http://mcp-erpnext:3012/mcp

## ملاحظات عن الموديل

gemini-2.5-flash اتلغى تمامًا لأي مشروع Google Cloud جديد (خطأ 404).
gemini-3.6-flash شغال بس حد الاستخدام المجاني اليومي ضيق جدًا (حوالي 20 طلب فقط).
gemini-3.1-flash-lite هو الاختيار الحالي، وحده اليومي أعلى بكتير.

## خطوات النشر والتحديث الصحيحة

تحذير أساسي: مجلد hagag-erp-src على السيرفر غير متزامن تلقائيًا مع الـ container. الكود الشغال فعليًا في الإنتاج هو اللي جوّه الصورة المبنية. أي تعديل لازم يترفع يدويًا للـ container.

الخطوات الصحيحة لأي تعديل:

خطوة 1: عدّل الملف محليًا في hagag-erp-src على السيرفر.

خطوة 2: انسخه لجوّه الـ container الشغال باستخدام أمر docker cp إلى المسار apps/hagag_erp/hagag_erp داخل الـ container.

خطوة 3: حدد نوع التعديل:
تعديل ملف Python فقط يحتاج فقط إعادة تشغيل الـ backend.
إضافة ملف JS أو CSS جديد أو تسجيله في hooks.py يحتاج bench build --app hagag_erp أولًا ثم إعادة التشغيل.
تغيير DocTypes يحتاج bench migrate.

خطوة 4: بعد التأكد إن التعديل شغال صح في الإنتاج، اعمل commit و push على GitHub.

## أخطاء وقعنا فيها فعليًا (عشان متتكررش)

مجلد باسم api موجود بالفعل جوّه الصورة المبنية (فيه whatsapp.py) حتى لو مش موجود في السورس المحلي وقتها. لو عملت ملف باسم api.py بايثون هيتجاهله تمامًا لصالح المجلد. تأكد دايمًا بأمر find أو ls جوّه الـ container قبل ما تفترض المسار.

أوامر bench console من غير خيار -T بترمي خطأ input device is not a TTY. لازم دايمًا exec -T مع أي إدخال عن طريق redirection.

موديلات Gemini بتتغير أو تتلغى فجأة. تأكد دايمًا من قائمة الموديلات المتاحة قبل ما تفترض اسم موديل شغال.

موديلات Gemini 3.x بترجع حقل thoughtSignature جوّه رد الأداة. لازم ترجع نفس الرد الأصلي بالكامل لما تبعت نتيجة الأداة تاني، وإلا هيرجع خطأ 400.

لو الذكاء الاصطناعي عنده أدوات برمجية متاحة، ممكن يشرح للمستخدم أسماء الأدوات دي بدل الشرح الطبيعي. لازم تعليمات نظام صريحة تمنعه من كده.
